## D. Encode dimension catalog (cross-cutting)

These config keys / evidence types recur; state packs flip them on/off and set values.

| Dimension | Typical Passage encode | Never Passage-decides |
|-----------|------------------------|------------------------|
| `jurisdiction_code` + `overlay_version` + effective date | Pack metadata | Whether FI enables jurisdiction |
| `statute_family` | Tag for template reuse | Legal classification opinion for a case |
| Acceptance timers | Business-day clocks / SLA | Whether deadline was legally met |
| Decision enum | accept / refuse / pending_supplemental | Correct legal outcome |
| Reason-code catalogs | Structured codes + free text | Whether a reason is “reasonable cause” |
| Evidence types | Instrument, affidavit, agent certification, PA acknowledgment, opinion, translation, e-journal, certified-copy flags | Sufficiency / authenticity |
| Notice delivery | Addresses, method, timestamp | Legal adequacy of notice |
| Extensions | Who/when/new deadline (TX-style) | Whether extension is authorized |
| Escalation flags | legal / fraud / BSA / APS (no SAR narrative) | Whether to file SAR / call APS |
| Receipt fields | Actor, decision, materials, policy pack, disclaimer | That authority exists |
| Privacy / retention | Role ACL, retention class metadata | GLBA/BSA retention number |

## E. False-claim / certification guardrails (apply to every row)

1. No UI/docs/sales language: “validated,” “certified POA,” “Passage confirms authority,” “safe harbor,” “counsel-approved pack” (counsel OFF active plan; packs are product models).
2. **M1 live claims = New York only.** Wave1 others = roadmap. Wave2 = R&D only.
3. Do not relabel generic `representative_certification` as PA §5601(d) Acknowledgment.
4. Passage never auto-accepts/refuses from statute alone without an FI decision actor.
5. UPOAA adopter counts from blogs are **orientation only** — archive a ULC snapshot before production pack freezes.
